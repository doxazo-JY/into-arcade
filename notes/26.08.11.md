# 데일리 노트 — 2026.08.11

## 오늘 요약 (공유용)

전날 중계 화면을 없앤 여파로 하루를 시작했다. "진행자가 팀 입장 여부를 확인할 수 있으면 좋겠다"는 요청으로 예전 중계 화면에 있던 정보(입장 완료/전)를 진행자 화면 팀 카드에 되살렸고, 팀 화면도 "상대팀이 아직 안 들어왔다"와 "라운드 시작을 기다리는 중"을 구분해서 보여주게 했다. 이어서 "중계 화면을 없앴더니 진행자가 상황 파악을 못 할 수도 있겠다"는 걱정으로, 예전 중계 화면에만 있던 시각 효과(배팅 대기 점 애니메이션, 결과 팝인)를 진행자 화면에도 옮겨왔다 — 다만 이 과정에서 사용자가 "점이 없는데?"라고 물어본 해프닝이 있었는데, 알고 보니 단순히 라운드를 아직 시작 안 해서였다(WAITING 상태에선 그 애니메이션들이 뜰 이유가 없음).

오후 들어 진행자 화면 전체를 다시 보면서 레이아웃을 정리했다. 버튼 순서가 "팀 카드 → 참가자 잠금 → 활성 이벤트 배너 → 다음 라운드(핵심 액션) → 이벤트 선택(사실 더 먼저 결정해야 할 것) → 게임 종료"로 뒤섞여 있다는 지적을 받아, 매 라운드 반복되는 흐름(이벤트 선택 → 라운드 시작)과 가끔 쓰는 설정(참가자 잠금, 게임 종료)을 분리해 재배치했다. 그 과정에서 이벤트 버튼 두 개("전체 점수 교환"이 "배팅 배수"보다 김)의 너비가 서로 달라서, 버튼 그룹 전체는 중앙 정렬돼도 정작 두 버튼 "사이의 틈"은 페이지 중앙에서 어긋나 보이는 미묘한 버그를 발견해 고쳤다(폭을 flex-1로 동일하게 맞춤). 진행자 화면의 그림자 효과가 일부 요소에만 걸려 있어 뒤죽박죽이라는 지적으로 화면 전체에서 아예 뺐고, 참가자 잠금/게임 종료 버튼도 같은 방식으로 너비를 맞췄다.

가장 오래 논의한 건 "라운드 시작" 버튼과 되돌리기 기능이었다. 처음엔 "굳이 라운드 시작 버튼이 있어야 하나, 자동으로 넘어가면 안 되나"는 제안이 나왔는데, 알고 보니 진행자가 아니라 다른 사람이 현장에서 조작할 예정이라는 맥락이 있었다 — 논의 끝에 "버튼을 없애기보다는, 그 버튼을 누르는 순간이 진행자가 '이제 배팅하세요'라고 말하는 타이밍과 정확히 맞아야 한다"는 결론으로, 흐름은 그대로 두고 1라운드 이후엔 버튼 라벨만 "라운드 시작"에서 "다음 라운드"로 바꾸는 선에서 정리했다. 되돌리기 논의는 더 길었다: ResultForm에 이미 적용 전 확인 단계가 있으니 사후 되돌리기는 필요 없다고 보고 라운드 결과·이벤트·점수 직접 수정의 되돌리기를 전부 제거했다가, 점수 직접 수정을 1팀/2팀 동시에 할 수 있게 통합하고, 그 수정 내역이 게임 종료 후 결과표에 하나도 안 보인다는 걸 발견해 이벤트와 같은 방식으로 라운드 표에 편입시켰다. 그런데 실제로 "승패를 잘못 눌렀다" 시나리오로 테스트해보니 점수 직접 수정으로 고치는 게 기록을 지저분하게 만든다는 걸 깨닫고 다시 되돌리기를 고민 — 예전 되돌리기 방식(라운드를 되돌려 재판정)은 `RoundResult`의 유니크 제약과 충돌한다는 걸 구현 전에 미리 찾아내서, 대신 기존 결과를 그 자리에서 업데이트하고 차액만 보정하는 "결과 다시 정하기"라는 더 단순한 기능으로 마무리했다.

## 오늘 한 일

### 1. 팀 입장 여부 표시 (진행자·팀 화면)

- 진행자 화면 팀 카드에 "✓ 입장 완료" / "입장 전" 표시 추가 — 예전 중계 화면에만 있던 정보
- 팀 화면의 대기 문구를 상대팀 입장 여부로 분기: "상대팀 입장을 기다리고 있어요" (미입장) vs "라운드 시작을 기다리고 있어요" (입장 완료, 라운드 시작 대기)
- 문구만 다르고 박스 모양이 같아 "안 읽으면 구분이 안 된다"는 지적으로, 상대팀 입장 대기는 상대 팀 컬러 강조선이 있는 실선 카드로, 라운드 시작 대기는 기존 점선 박스로 스타일 자체를 다르게 함

### 2. 진행자 화면에 배팅 대기 애니메이션·결과 팝인 추가

- 예전 중계 화면에 있던 배팅 대기 중 점 애니메이션(`wait-dot`), `GameInProgressBadge`, 결과 WIN!/LOSE! 팝인(`animate-pop-in`)을 진행자 화면에 옮김
- 팀 입장 대기 상태에도 같은 점 애니메이션 적용 — "너무 정적으로 느껴진다"는 지적 반영
- 배팅 배수 이벤트 팝업 문구를 "자세한 내용은 결과에 반영됩니다"라는 두루뭉술한 문장에서 "이번 라운드는 배팅한 포인트의 N배를 얻거나 잃게 됩니다"처럼 실제 배수 값을 보여주는 문장으로 교체(`getVisibleEventForTeam`에 `multiplier` 필드 추가). 이후 문구가 어색하게 줄바꿈되는 문제는 `<br />`로 개행 위치를 직접 지정해서 해결
- 커밋 메시지에 이전 세션의 무관한 메시지가 잘못 들어간 실수를 발견해 즉시 `git commit --amend`로 수정(아직 푸시 전이라 안전하게 고침)

### 3. 진행자 화면 레이아웃 재배치

- 버튼 순서를 "팀 카드 → (입장 안 한 팀 안내) → 활성 이벤트 배너 → 이벤트 선택 → 라운드 시작/다음 라운드 → 판정 폼 → (하단) 참가자 잠금·게임 종료"로 재배치 — 매 라운드 반복되는 흐름과 가끔 쓰는 설정을 분리
- `GameFlowPanel` 내부에서 이벤트 패널을 라운드 시작 버튼보다 먼저 렌더링하도록 순서 변경
- 이벤트 버튼 두 개의 너비가 텍스트 길이에 따라 달라서 버튼 "사이의 틈"이 페이지 중앙과 어긋나 보이는 문제 발견 — `flex-1`로 동일 너비를 되돌리고 컨테이너를 `max-w-sm` + `mx-auto`로 좁혀 중앙 정렬을 다시 보장(그 과정에서 `GameFlowPanel`/`section`이 `w-full`을 제대로 전파하지 않던 버그도 같이 고침)
- "게임 진행 중" 배지를 진행자 화면에서 제거 — 판정 폼(`ResultForm`)이 이미 같은 타이밍에 뜨니 중복이라는 판단(팀 화면에는 그대로 유지)
- 진행자 화면(룸 콘솔) 전체에서 그림자 효과(`shadow-sticker`)를 제거 — 일부 요소에만 걸려 있어 뒤죽박죽이었음
- 참가자 화면 잠그기 / 게임 종료 버튼 너비를 이벤트 버튼과 같은 방식(`flex-1` + `max-w-sm`)으로 통일하고 중앙 정렬

### 4. "라운드 시작" 버튼 흐름 재검토

- "굳이 버튼이 있어야 하나, 결과 판정 → 자동으로 다음 라운드 → 자동으로 배팅 오픈"이 낫지 않겠냐는 제안으로 시작 — 그런데 이 사이트를 진행자 본인이 아니라 다른 사람이 조작할 예정이라는 맥락이 확인되면서, "적을수록 좋다"보다는 "말로 진행하는 흐름과 버튼 클릭이 정확히 맞아떨어져야 한다"는 쪽으로 방향이 바뀜
- 결과 확정과 다음 라운드 생성을 한 번에 합치는 안도 검토했으나, 그러면 팀 화면의 WIN!/LOSE! 결과 팝업이 뜰 시간 없이 다음 라운드로 넘어가버리는 문제를 미리 발견해 폐기(팀 화면은 폴링 기반이라 RESOLVED 상태를 거치지 않으면 결과를 못 봄)
- 최종적으로 흐름은 그대로 두고, 1라운드에서만 "라운드 시작"이라는 라벨을 쓰고 2라운드부터는 같은 버튼이 "다음 라운드"라고 표시되도록 라벨만 변경(`roundNo` prop을 `GameFlowPanel` → `RoundControls`로 전달)

### 5. 되돌리기 기능 전면 재검토

- **1차: 사후 되돌리기 제거, 적용 전 확인으로 전환** — `ResultForm`처럼 적용 전에 확인 화면을 거치면 사후 되돌리기가 굳이 필요 없다는 판단으로, 라운드 결과·이벤트·점수 직접 수정 되돌리기(`undoRoundResult`/`undoManualAdjust`)를 제거하고 "점수 직접 수정"에도 같은 확인 단계를 추가. 배팅 배수 이벤트 취소(`undoEvent`)만 성격이 달라(아직 결과가 안 나온 진행 중인 상태를 취소하는 것) 그대로 남김 — 다만 이것도 라운드가 BETTING으로 넘어간 뒤엔 흐름이 꼬인다는 판단으로 WAITING 상태에서만 가능하도록 제한(UI·서버 액션 양쪽에 가드)
- 게임 종료(`Room.status === "ENDED"`) 후에는 점수 직접 수정 자체를 막음(UI에서 폼을 안내 문구로 대체, 서버 액션에도 동일 가드) — 최종 순위 발표 후 실수로 점수가 바뀌는 사고 방지
- "기록/되돌리기" 페이지 제목을 "기록"으로 정리했다가, "수정도 할 수 있다는 걸 보여주는 게 좋겠다"는 피드백으로 "기록/점수 수동 수정"으로 다시 변경
- **점수 직접 수정 통합**: 1팀/2팀을 따로 두 번 제출해야 했던 걸, 값을 입력한 팀만 골라 하나의 트랜잭션으로 함께 적용하도록 통합(`manualAdjustScores`)
- **점수 직접 수정을 라운드 결과표에 표시**: 게임 종료 후 라운드별 결과표에 점수 직접 수정 내역이 전혀 안 보인다는 문제 발견 — 처음엔 별도 표로 분리했다가 "이벤트처럼 그 시점에 표시되는 게 낫다, 표를 굳이 하나 더 두지 말자"는 피드백으로 전체 점수 교환 이벤트와 같은 방식으로 라운드 행에 통합(`manualAdjustScores`가 조작 시점의 "지금 라운드"에 묶어서 저장)
- **표시 순서 버그 수정**: "1라운드 끝난 뒤에 수정했는데 이게 맞아?"라는 질문으로, 결과 확정 후에 한 수정도 무조건 라운드 행 "앞"에 표시되던 버그를 발견 — `RoundResult.appliedAt`(결과 확정 시각)과 비교해 그 전이면 라운드 행 앞에, 후면 뒤에 넣도록 수정(`manualAdjustsBefore`/`manualAdjustsAfter`로 분리)
- **결과 다시 정하기로 최종 정리**: "승패를 잘못 입력했다" 시나리오로 실제 테스트해보니 점수 직접 수정으로 고치면 기록이 지저분해진다는 걸 확인 — 라운드 결과 되돌리기를 다시 살릴지 검토하다가, 예전 방식(되돌리기 → `RESULT_PENDING` → 재판정)은 `RoundResult`가 `(roundId, teamId)` 유니크 제약이 있어서 되돌린 행이 남은 채로 재판정 시 새로 `create`하면 충돌한다는 문제를 구현 전에 미리 발견. 대신 기존 `RoundResult` 행을 그 자리에서 업데이트하고 차액(정정 후 delta − 정정 전 delta)만큼 보정 트랜잭션 하나를 적용하는 "결과 다시 정하기"(`CorrectResultButton`, `correctRoundResult`)로 구현 — 중간 상태 없이 라운드는 계속 RESOLVED를 유지하고, "다음 라운드"를 누르기 전에만 버튼이 노출돼 자연스럽게 시점 제약이 걸림
- 결과 정정이 있어도 라운드 결과표의 "전/후 포인트" 표시가 "라운드 시작 전 → 최종(정정 반영) 점수"로 보이도록 `betTxMap` 집계 로직도 같이 수정(중간의 틀렸던 상태가 안 섞여 보이게)
